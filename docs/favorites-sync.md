# 관심 목록의 기기 간 동기화 제안

2026-11-01. 이번 작업에서는 설계만 정리했으며 자동 동기화나 로그인을 켜지 않았다.

현재 별표는 `ani.feentn.com`의 브라우저 `localStorage`에 작품 ID 배열로 저장된다. 같은 기기의 다른 탭은 저장 이벤트로 반영하지만, 휴대폰·PC·다른 브라우저 사이에는 공유되지 않는다. 기존 JSON 백업 불러오기는 합집합으로 추가하므로 다른 기기에서 지운 별표까지 반영하는 동기화는 아니다.

## 추천: Google 로그인 후 자동 동기화

사용 흐름은 **기존처럼 별표 사용 → 원하는 때 Google 로그인 → 현재 목록 합치기 → 다른 기기에서 같은 계정으로 로그인**이다. 로그인 후에는 별표 등록·해제가 자동으로 오간다. 처음 한 번만 현재 브라우저 목록과 서버 목록을 미리 보고 합친다. 로그아웃해도 서버 목록이 삭제되지는 않으며, 공용 기기에서는 로컬 목록도 비우는 선택지를 제공한다.

현재 Cloudflare Pages를 유지하고 Pages Functions 또는 Worker에 인증·목록 API, D1에 사용자별 별표를 저장하는 구성이 적합하다. Google 로그인은 익숙하고 기기를 잃어버려도 같은 계정으로 복구하기 쉽다. Google Cloud 프로젝트의 OAuth 클라이언트와 도메인 등록은 초기 설정이 필요하다.

| 방식 | 다른 기기에서 할 일 | 장점 | 제약 |
| --- | --- | --- | --- |
| 현재 JSON 백업 | 파일 보내기·불러오기 | 계정과 서버 없이 사용 | 자동 반영 안 됨, 삭제 동기화 안 됨 |
| 기기 연결 QR·복구키 | QR 읽기 또는 긴 복구키 입력 | 회원가입 없이 연결 | 키를 잃으면 복구 어려움, 링크를 가진 사람이 목록에 접근할 수 있어 회수·재발급 설계 필요 |
| Google 로그인 + 서버 저장 | 같은 계정으로 로그인 | 자동 동기화와 복구가 편리 | 인증·서버·개인정보 처리와 초기 OAuth 설정 필요 |

한 사람이 두 기기에서만 쓰더라도 로그인 방식이 복구와 운영 면에서 편하다. 계정 없는 사용을 우선한다면 QR 방식이 차선이다. QR 자체는 동기화가 아니라 서버의 같은 목록에 접근할 자격을 다른 기기로 옮기는 절차다. URL에 별표 배열을 담는 공유 링크도 일회성 복사일 뿐 자동 동기화는 아니다.

## 구현 시 꼭 다룰 동작

- 기존 `manga-shelf-favorites-v1`과 작품 ID를 유지한다. 서버 키는 Google의 안정적인 사용자 식별자 `sub`와 작품 ID를 조합한다. 이메일 주소를 작품 데이터 CSV에 넣지 않는다.
- 전체 배열을 덮어쓰지 않고 작품별 등록·해제를 저장한다. 해제도 삭제 기록으로 남겨 오래된 기기의 목록 때문에 별표가 되살아나지 않게 한다.
- 서버가 부여하는 변경 순서와 버전을 사용한다. 같은 작품을 두 기기가 동시에 바꾸면 서버에서 나중에 승인한 변경으로 맞추고 충돌 시 최신 상태를 다시 가져온다. 기기의 시계만으로 우선순위를 정하지 않는다.
- 오프라인에서는 로컬에 먼저 저장하고 변경 큐를 남긴다. 재접속·페이지 복귀 시 재시도하고 서버 상태와 맞춘다. 실패·로그인 만료 시 로컬 목록을 지우지 않는다.
- 쓰기 요청을 지연 묶음 처리하고 탭·화면 복귀 시 갱신한다. 계속 연결되는 소켓이 필요한 규모는 아니다.
- 서버에서 ID 토큰·세션과 사용자별 접근을 검증한다. 세션은 HttpOnly·Secure 쿠키로, 쓰기 API에는 출처·CSRF 검증을 적용한다. 토큰·복구키를 공개 CSV, GitHub, 로그 또는 검색 가능한 URL에 저장하지 않는다.
- 내보내기와 계정 데이터 삭제를 제공한다. 관심 목록을 공개 목록과 분리하고 선택한 기기의 연결을 해제할 수 있게 한다.

완료 기준은 PC에서 추가한 별표가 휴대폰에 나타나고, 휴대폰에서 해제한 별표가 PC에서 사라지는 것, 오프라인 충돌·재로그인·기존 백업이 안전하게 처리되는 것이다. 로그인 UI만 붙인 것을 동기화 완료로 보지 않는다.

## 확인한 공식 문서

- [Cloudflare D1](https://developers.cloudflare.com/d1/): Workers·Pages에서 사용하는 서버 데이터베이스.
- [Google OpenID Connect](https://developers.google.com/identity/openid-connect/openid-connect): 로그인 자격 증명, 리디렉션 URI, ID 토큰 검증과 초기 프로젝트 설정.
